### 1.2 Core agent loop (ByokOrchestrator.js and friends)

- `[fixed]` **B-CORE-1 (high)** — `resolveConnectionForCallKind` resolves `temperature`/`maxTokens` through the profile + per-model overlay but returns only baseUrl/apiKey/modelName (`ByokOrchestrator.js:516-551`); `callModel`'s `chatOptions` (`:747-753`) and the compaction summarizer (`:1573-1587`) never send them. - `[fixed]` **B-CORE-2 (high)** — when the repeated-tool-call loop guard stops a batch, only the stop-triggering call receives a tool output (`ByokOrchestrator.js:1256-1265`); sibling calls in the same assistant message (before/after the stop, and corrective-classified ones) are orphaned, leaving `tool_calls` without matching `tool` messages. `byok-repeated-tool-call-loop` is not in `NON_RETRYABLE_BYOK_ERROR_CODES`, so Retry replays the protocol-invalid transcript and strict endpoints (OpenAI, vLLM) reject it with 400 — permanently bricking the chat. - `[fixed]` **B-CORE-3 (medium)** — the system-prompt snapshot invalidation key is only `hasOpenedProject()` (`ByokOrchestrator.js:627-645`). - `[fixed]` **B-CORE-4 (medium)** — the always-on "latest 2 images" window recomputes survival on every build (`ByokOrchestrator.js:694-705`, `ByokTranscript.js:261-297`): a 3rd capture retroactively rewrites earlier transcript messages (tool outputs get a placeholder, user attachments silently lose parts), re-busting the provider prefix cache mid-loop — exactly what Phase 14.1 removed. Image survival is now monotonic: an image once sent stays replayed until context pressure explicitly evicts it.
- `[fixed]` **B-CORE-5 (medium)** — after a first compaction the transcript head is `[summary(user), preserved(user), …]`; `findKeptTurnsStartIndex` counts those synthetic messages as turns, so the next compaction re-summarizes the summary and re-prepends a regenerated preserved block while usage stays ≥75% — a per-round churn of one extra summarizer call plus a full history rewrite, until the chat dead-ends at `byok-context-full`. - `[fixed]` **B-CORE-6 (low)** — one `watchdog.notifyActivity('tool-executing')` per batch (`ByokOrchestrator.js:1337`); sub-agent runs and long tool executions produce false "no activity for 90s" stall notices while tools are legitimately working. Activity is now notified per tool call.
- `[fixed]` **B-CORE-7 (low)** — stale comment at `ByokOrchestrator.js:1507-1508` still describes the pre-14.1 "snapshot folded into the last user message" shape. Reworded.

### 1.4 RAG subsystem

- `[fixed]` **B-RAG-1 (high)** — `loadPersistedByokRagIndex` (`ByokRagBuildService.js:133-153`) is exported and never called: after every app restart the in-memory runtime is gone, nothing reloads `<userData>\byok-rag\index.json`, and `search_knowledge` silently answers lexical mode while the status card claims a built index — recovery demands a ~30-minute rebuild or bundle re-download. The loader is now wired lazily into the search deps path and on settings-tab mount (with corpus-hash + embedder checks).
- `[fixed]` **B-RAG-2 (high)** — Qdrant collection dimensions compute `atob(v).length * 3 / 4 / 4` (`ByokRagStorage.js:155-158`): `atob` already returns decoded bytes, so the base64 factor is applied twice — a 384-dim index creates a 288-dim collection and every Qdrant upload then fails 400 after the full embedding pass, permanently (the wrong collection exists and is never recreated). Fixed to `length / 4`; an existing wrong-sized collection is now dropped and recreated.
- `[fixed]` **B-RAG-3 (high)** — the docs-folder reader requires `electron.remote` (`ByokRagBuildService.js:160-166`), removed in Electron 14 (this app runs Electron 32): the opt-in local docs folder silently indexes zero files on desktop. `remote` requirement dropped (`fs`/`path` are available via nodeIntegration).
- `[fixed]` **B-RAG-4 (medium)** — Qdrant setup draws a fresh ephemeral port every launch while the renderer persists `qdrantBaseUrl` only on explicit setup/restore clicks; after a restart preferences point at a dead port and the next rebuild fails with connection-refused after full embedding. The setup now prefers reusing the previous endpoint's port when free.
- `[fixed]` **B-RAG-5 (medium)** — `spawnQdrant` overwrites `qdrantChild` without killing the previous one, health-check failure never kills the just-spawned child, and `before-quit` kills only the last child (`ByokQdrant.js:127-141, 297-306`) — orphaned `qdrant.exe` processes contending for the same storage dir. Setup is serialized (single shared promise), re-spawn kills the previous child, and quit kills all tracked children.
- `[fixed]` **B-RAG-6 (medium)** — a mid-build embedder throw (WASM OOM at chunk ~3000) propagates out of `rebuildByokRagIndex` despite its "never a throw" contract; the settings tab's `setIsBuilding(false)` is unreachable and the button stays "Building…" until the dialog is reopened. Build is now try/caught into `{ok:false,error}`.
- `[fixed]` **B-RAG-7 (medium)** — Rebuild stays enabled during a bundle import and vice versa (`ByokRagSettingsTab.js:458-465, 504-517`); both write the same `index.json` + runtime — silent last-writer-wins. Single synchronous busy flag gating both, set before the consent await.
- `[fixed]` **B-RAG-8 (medium)** — newest-bundle selection sorts release tags lexicographically (`ByokRagBundle.js:167-175`): `v9` beats `v10` forever once a 10th generation exists. Numeric-aware compare added.
- `[fixed]` **B-RAG-9 (medium)** — `deserializeByokRagIndex` accepts NaN/Infinity vectors, non-uniform vector lengths, non-multiple-of-4 base64, and manifest/chunk-count mismatches; `byokRagCosineSimilarity` silently truncates dimension mismatches via `Math.min` (`ByokRagIndex.js:41-51, 191-243`). Validation added; similarity refuses length mismatch.
- `[fixed]` **B-RAG-10 (medium)** — `isByokRagIndexUpToDate` compares only the embedder id while its docblock claims corpus+embedder (`ByokRagIndex.js:119-122`); the corpus hash also excludes `tags` and concatenates without separators (boundary collisions). Corpus hash now folds tags with delimiters; up-to-date compares the live corpus hash too.
- `[fixed]` **B-RAG-11 (medium)** — index persistence is a single `writeFileSync` overwrite (`ByokRagFiles.js:44` via `ByokRagStorage.js:86-88`): an interrupted write destroys the existing working index. Atomic temp+rename added.
- `[fixed]` **B-RAG-12 (low)** — IndexedDB backend ignores `transaction.onabort` (`ByokRagFileBackends.js:70-82`): a quota abort after a successful put resolves as success (silent data loss on web). Abort now rejects; writes resolve from `oncomplete`.
- `[fixed]` **B-RAG-13 (low)** — Qdrant point ids are FNV-1a u32 hashes of chunk ids (`ByokRagStorage.js:115-122`): ~0.2% birthday collision at 4,026 chunks silently drops a chunk via upsert overwrite. Point id is now the deterministic chunk index.
- `[fixed]` **B-RAG-14 (low)** — the chunker splits on blank lines inside fenced code blocks and sentence-splits long fences (`ByokRagCorpus.js:51-56`), producing unbalanced-fence chunks for user docs folders (the shipped corpora are unaffected — verified). Fence-aware pre-splitting added.
- `[fixed]` **B-RAG-15 (low)** — the embedder passes the removed v2 `quantized: true` option (`ByokRagEmbedder.js:89-93`); q8 loads only because the v4 wasm device default happens to be q8 — any upgrade silently diverges query-side from the pinned-q8 prebuilt bundles. Now pins `dtype: 'q8'` explicitly (matches the bundle builder).
- `[fixed]` **B-RAG-16 (low)** — Qdrant `requestJson` has no timeout (`ByokQdrant.js:207-247`): a wedged Qdrant freezes the restore button forever. Timeout + destroy added.
- `[fixed]` **B-RAG-17 (low)** — snapshot restore DELETEs the existing collection before the upload is known-good and leaves wrong-dim restored collections in place on refusal (`ByokQdrantSetupCore.js:251-257, 304-312`), poisoning later rebuilds. Failure paths now clean up the leftover collection.
- `[fixed]` **B-RAG-18 (low)** — lexical mode (RAG off / pre-restart) ignores a bare `chunk_id` and then claims "a chunk_id alone suffices" in the error (`ByokRagSearch.js:151-174`). The neighbor read now works from the lexical corpus without an index.
- `[fixed]` **B-RAG-19 (low)** — the Qdrant archive download opens the write stream before the status check and recurses on redirects: the first stream and each 3xx response leak, with no redirect cap (`ByokQdrant.js:41-74`). Redirect walk now opens the stream only on the final 2xx, caps at 5 hops, and destroys redirect responses.

### 1.5 MCP server

- `[fixed]` **B-MCP-1 (high)** — `notifications/cancelled` is a JSON-RPC notification (no id) and main answers 202 WITHOUT forwarding (`ByokMcpServer.js:173-177`), while the renderer protocol core implements a real cancel handler for it: client cancellation is dead end-to-end, the tool keeps executing, and the serialized queue keeps its slot. Notification forwards added (fire-and-forget to the picked sender).
- `[fixed]` **B-MCP-2 (medium)** — the stdio adapter retries ANY fetch failure once, including a connection reset AFTER the server executed the message (`gdevelop-mcp-stdio.js:163-183`) — at-least-once execution of mutating tools. Retry is now restricted to connection-refused/dns (endpoint down before delivery).
- `[fixed]` **B-MCP-3 (medium)** — the tool host queue tail advances only when the underlying call settles (`ByokMcpToolHost.js:161-166, 278-296`); a never-settling tool (hung preview wait) blocks every subsequent MCP call until reload, each burning the full 120s timeout. The tail now advances on timeout as well.
- `[fixed]` **B-MCP-4 (medium)** — second-instance refusal trusts pid liveness alone (`ByokMcpServer.js:257-272`); Windows pid reuse after a crash makes an unrelated process "own" the endpoint forever. A live pid is now additionally verified via an authenticated `/health` probe before refusing; a dead/stale owner is taken over.
- `[fixed]` **B-MCP-5 (low)** — bearer token compared with `!==` (not timing-safe) and the disabled-state 503 precedes auth (state leak) (`ByokMcpServer.js:80-84, 205-215`). Timing-safe compare; both states answer 403 for unauthenticated callers.
- `[fixed]` **B-MCP-6 (low)** — the discovery file (contains the token) is written with default 0644 on POSIX (`ByokMcpServer.js:290-295`) — other local users can drive the read-write tool surface. Now 0600.
- `[fixed]` **B-MCP-7 (low)** — `sender.once('destroyed')` re-registered on every readiness announcement (`ByokMcpServer.js:374-376`) — listener pileup past 11 Ask-AI toggles. Guarded to once per sender.
- `[fixed]` **B-MCP-8 (low)** — `forwardCounter` resets per server cycle while the response handler reads the current state's pending map with no generation check (`ByokMcpServer.js:304-310, 378-387`): a late renderer response after an off→on toggle can answer the NEXT cycle's same-numbered request. Counter is now monotonic across cycles.
- `[fixed]` **B-MCP-9 (low)** — the internal-error catch discards the request id (`useByokMcpServer.js:223-232`), violating JSON-RPC 2.0 id echo. Now echoes the parsed id when determinable.
- `[fixed]` **B-MCP-10 (low)** — the 413 body-cap response is destroyed before it can flush (`ByokMcpServer.js:188-192`); clients see a network error and the adapter reports "is GDevelop running?" instead of "too large". Response now flushes with `Connection: close`.
- `[fixed]` **B-MCP-11 (low)** — server error bodies with no top-level id (batch arrays, empty 4xx bodies) are silently swallowed by the stdio adapter (`ByokMcpStdioAdapterCore.js:145-150`) — legacy batch clients hang forever. The adapter synthesizes a JSON-RPC error for unanswered requests on ≥400 with no relayable body.
- `[fixed]` **B-MCP-12 (low)** — the stdio pump fires unbounded concurrent fetches per stdin line and ignores stdout backpressure (`gdevelop-mcp-stdio.js:206-210`). Chained through a small serial queue honoring drain.
- `[fixed]` **B-MCP-13 (low)** — the activity ring is per-renderer module state while main routes calls to the focused window: the settings card misses other windows' activity (`ByokMcpToolHost.js:138`). Fixed 2026-10-02 the OOS-prescribed way: the tool host exposes `subscribeByokMcpActivity`, the seam hook mirrors every recorded entry to main over `byok-mcp-activity`, main keeps a validated 200-entry aggregate surfaced in the `byok-mcp-status` response, and the card merges local + remote (pure `mergeByokMcpActivity`, composite-key dedupe, capacity-capped, local-only fallback when IPC is absent).
