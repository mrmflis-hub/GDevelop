# Full BYOK audit — 2026-10-02 second pass (audit100226)

Scope: the whole BYOK feature (`newIDE\app\src\AiGeneration\Byok\`, ~37k lines of
source plus specs), the Electron main BYOK handlers, the scripts/evals, and every
upstream editor file BYOK calls.

Method: TEN read-only audit subagents in two waves — caching, tool layer, agent
loop, RAG, persistence/UI (wave 1); MCP, Electron handlers, prompt+scripts,
upstream-called files, and regression-hunting on the previous session's fixes
(wave 2) — followed by orchestrator verification of every critical/high claim
against the real source. Each fix below was regression-guarded by reverting it
and watching the new test go red.

Relation to `audit011026.md`: that audit closed 63 findings on 2026-10-01/02. It
is NOT superseded. This pass deliberately targeted ground it did not cover —
caching in depth, the tool layer's ergonomics, the upstream files BYOK abuses,
and **regressions introduced by the fixes themselves** (two of the highest-value
findings below are exactly that).

Status tokens: `[fixed]` (fixed + tested this session), `[open]` (triaged, not
fixed), `[verified]` (checked, no defect found).

---

## Part 1 — Critical and high findings

### 1.1 Caching

- `[fixed]` **[A1002-CACHE-1] (high — REGRESSION of the B-CORE-3 fix)** — the
  system-prompt snapshot's invalidation key declared
  `systemPromptSnapshotNotesIdentifier`, compared it, and **never assigned it**
  (`ByokOrchestrator.js:676,693` vs `:720-721`). With a project open the
  identifier is non-null, so the three-way check failed on every round: the
  ~5.4k-token prompt was recomposed from scratch every round, the notes and
  skill metadata were re-read, and — the actual cost — after the model's first
  `update_project_notes` write the recomposed system message changed bytes
  mid-loop, busting the provider prefix cache from position zero. This silently
  defeated the whole point of Phase 14.1 (D14-1), which is claimed
  "spec-proven" and green. One-line fix + a real assertion.

- `[fixed]` **[A1002-CACHE-2] (medium — a vacuous test)** — the spec claimed to
  prove byte-stability "including after update_project_notes", but its executor
  mock flipped a flag from `functionCall.function.name` while the orchestrator
  passes `{name, arguments, call_id}` **and** `update_project_notes` is an
  intercepted tool that never reaches the executor. The flag never flipped, the
  notes never arrived, and the assertion passed against broken code — which is
  why CACHE-1 shipped. The spec now drives the real storage pair
  (`saveByokProjectNotes`) and asserts the prompt composer ran **exactly once**.
  *Generalizable lesson recorded: a test that cannot reach its scenario is worse
  than no test — it manufactures false confidence.*

- `[fixed]` (session 2) **[A1002-CACHE-4] (low)** — `ByokModelsCache.js:98-131` keys the
  per-session model cache by normalized base URL only, not by key/provider: two
  providers sharing one endpoint URL with different keys overwrite each
  other's model list (and the orchestrator reads A's server-reported context
  window for B's model).

- `[fixed]` (session 2, CACHE-5 and CACHE-6) / `[open]` (CACHE-7, CACHE-8) —
  avoidable costs: the 2.3 MB minified-docs artifact is re-validated and re-copied on
  every accessor call (memoize); every lexical query lowercases the whole
  ~4k-chunk pool per query (precompute a lowercase view); `readByokRagIndexStatus`
  deserializes the entire multi-MB index to read four manifest fields (sidecar
  or cache); the persisted-index recovery builds the corpus only to hash it,
  then rebuilds the identical corpus for the lexical cache (share one build).

### 1.2 The agent loop

- `[fixed]` **[A1002-LOOP-1] (high)** — an exception escaping between the
  assistant `tool_calls` message being recorded and its outputs being appended
  orphaned the unanswered calls, persisting a protocol-invalid transcript whose
  error code was retryable — so Retry replayed the same broken transcript and
  strict endpoints 400'd it forever (the B-CORE-2 brick class). Two concrete
  holes: the per-batch `flushByokExtensionRegeneration` await
  (`ByokOrchestrator.js:1437`) and a rejecting `onRequestEditApproval`
  (`:1370`) — both outside the containment the code comment at `:1443-1448`
  claims guarantees the invariant. Fixed three ways: each await is contained,
  **and** a new `answerPendingToolCalls` sweep runs at the end of every batch,
  answering only the calls that still lack an output (so it can never
  duplicate one). Three regression tests; the reload one is proven non-vacuous
  by a `reloadAttempted` flag and verified to fail with both protections
  removed.

- `[fixed]` **[A1002-LOOP-2] (high)** — compaction structurally could not fire
  in the flagship shape. Both cut points were **user-turn** boundaries and the
  function bailed when `turnsStart === 0`; a single mega-turn build chat (one
  user message, 50-100 tool rounds — the documented shape) never has 11 user
  turns, so it got no compaction at all and dead-ended at the **non-retryable**
  `byok-context-full`, contradicting the compactor's own docblock ("the
  byok-context-full dead-end becomes a recoverable event"). Fixed with a
  **round-based** fallback boundary for the tool-output trim
  (`findKeptToolRoundsStartIndex`), which needs no turn boundary; when there is
  no turn boundary the pass is a tool-output-only trim (no summary prepended),
  which keeps every `tool_calls`/output pair intact by construction. Three new
  tests, including one asserting the pairs survive.

- `[fixed]` **[A1002-LOOP-3] (medium)** — the "shared parent+children" turn
  budget was not shared: the sub-agent runner got a fresh `{remaining: 150}` and
  the parent orchestrator minted its own second 150
  (`useByokChatSeam.js:1229` + `ByokOrchestrator.js:395`), so a chat plus its
  sub-agents could spend double the documented cap while the exhaustion message
  claimed otherwise. One budget object now created once and passed to both.

- `[fixed]` (session 2) **[A1002-LOOP-4] (low)** — `ByokClient.js` response validation pins
  `tool_call.id` and `function.name` but not `message.content` shape or
  `function.arguments` type: a gateway returning content as an array of parts
  makes every turn end in `byok-empty-answer`; a server omitting `arguments`
  produces a replay that strict endpoints reject with 400 (retryable → brick).

- `[fixed]` (session 2) **[A1002-LOOP-5/6] (low)** — the compaction summarizer call carries no
  cancellation handle, so Stop does not abort it (the client explicitly promises
  it does); and `byok-turn-budget-exhausted` is missing from
  `NON_RETRYABLE_BYOK_ERROR_CODES`, so Retry is a dead button that re-marks the
  identical error forever.

### 1.3 Tools

- `[fixed]` **[A1002-TOOL-1] (medium — REGRESSION of the B-TOOL-3 fix)** —
  `add_external_events` still validated AFTER mutating: the sheet is created
  (`:271`) and associated (`:276`) before the both-arguments conflict check
  (`:282`) and before `validateByokEventScript` (`:293`), while the fix's own
  comment at `:287` claims "validated BEFORE the sheet is created". A failure
  reports `didModifyProject:false` on a mutated project — breaking the
  approval/dirty gating — and the model's retry then finds the sheet already
  created. Both checks now run before any mutation.

- `[fixed]` (session 2) **[A1002-TOOL-3] (medium)** — `inspect_runtime_state` advertises
  `scene_name` and `variable_paths` but the handler never reads `args`
  (`ByokRuntimeTools.js:398-424`): both filters are dead and the model always
  receives the full multi-scene dump, which `capToolOutput` then cuts mid-JSON
  at 20k chars — possibly without the scene it asked for and with no tool-level
  `truncated` flag. Either honor the filters or drop them from the schema.

- `[fixed]` (session 2) **[A1002-TOOL-4] (medium)** — `list_effects` has no tool-level cap:
  ~46 stock effects serialize to ≈21-22k chars, at/over the 20k output cap, so
  the array is cut mid-JSON and the usage `note` explaining `changed_effects`
  is lost. Needs the `STARTER_LIST_CAP` treatment (cap + `truncated` + total).

- `[fixed]` (session 2) **[A1002-TOOL-5/6] (low)** — the compaction preserved block reads
  `args.skillName` while `load_skill` uses `name`, so "Loaded skills" is always
  empty after a compaction; and `read_events_source`'s `max_chars` description
  teaches "default 30000" while the implementation defaults to 12000.

- `[fixed]` (session 2) **[A1002-TOOL-7] (low)** — loop-guard fingerprints are recorded for
  calls that never execute (approval refused / suspended mid-approval), so the
  corrective and stop thresholds are reachable with zero executions and a chat
  can die with "repeated tool call" for a tool that never ran.

- `[fixed]` (session 2) **[A1002-TOOL-8] (improvement)** — the loop guard only detects a
  trailing streak of identical fingerprints, so a real infinite loop that
  alternates A,B,A,B never exceeds streak 1 and runs to the round cap. Cycle
  detection over the kept history would catch it.

- `[fixed]` (session 2) **[A1002-TOOL-11] (improvement, also PROMPT-2)** — `read_doc_page` is
  advertised only in the **no-project** tool set, yet the always-on retrieval
  map, the `search_knowledge` schema text and every `docs-min` corpus chunk
  teach it ("Full page: read_doc_page('<path>')"). With a project open — the
  common docs-lookup case — the prompt invites a call whose schema is not in the
  turn's `tools` array, contradicting the prompt's own "only call the tools
  listed below".

### 1.4 RAG

- `[fixed]` (session 2) **[A1002-RAG-1] (high)** — **the Qdrant backend is upload-only.**
  `qdrantSearch` is declared (`ByokRagSearch.js:107`), consumed (`:219`), and
  **never provided by any production deps source**; `loadPersistedByokRagIndex`
  refuses any backend but `in-process` (`ByokRagBuildService.js:153`). After any
  restart, Qdrant users silently degrade to lexical forever while the settings
  card reports healthy — and the untested `qdrantSearch` branch is exactly why
  nobody noticed. Also untested: the whole backend=qdrant deps path.

- `[fixed]` (session 2) **[A1002-RAG-2] (medium)** — `saveIndex` upserts points 1..N but never
  deletes points beyond N (`ByokRagStorage.js:145,170-191`), so a **shrinking**
  corpus leaves stale chunks searchable in an existing right-sized collection.
  Covered by tests only for exact-size and wrong-size collections, never smaller.

- `[fixed]` (session 2) **[A1002-RAG-3] (medium)** — the Qdrant snapshot restore uses
  `?wait=true` under the same 30 s timeout added for wedged health checks; a
  large snapshot aborts client-side and the failure path then **deletes the
  collection** while the server may still be restoring it.

- `[fixed]` (session 2) **[A1002-RAG-5] (medium)** — the lexical half is AND-of-substrings
  with no stemming, prefix, or OR fallback (`ByokRagSearch.js:51-60`), so one
  absent or morphologically different term zeroes the entire result — and this
  is the mode every user gets before building an index (RAG is off by default).
  The tool answers `success:true` with 0 hits although the chunk exists. The
  24-query eval set was authored to AND-match its targets, so the ≥70% gate can
  never catch this class.

### 1.5 Upstream files BYOK calls

- `[fixed]` **[A1002-UP-9] (high)** — the MCP tool-execution path never called
  `triggerUnsavedChanges`, so an external MCP agent's mutations left the editor
  reporting "no unsaved changes" and **every edit was silently lost on close**
  (`useByokChatSeam.js`, both `executeRegistryTool` and `executeExtraTool`). The
  chat path marks dirty in `onFunctionCallsExecuted`; the MCP host used the bare
  executor with no dirty-marking. Both paths now bridge `didModifyProject` to
  `triggerUnsavedChanges`.

- `[fixed]` **[A1002-UP-10] (high)** — `flushByokExtensionRegeneration` was only
  ever called by the chat orchestrator, so extension-authoring tools invoked
  **over MCP** never regenerated: created functions/behaviors stayed unusable in
  events until an unrelated chat batch happened to flush. The MCP host now
  flushes after the extra-tool step (contained, so a reload failure never turns
  a successful tool result into an error).

- `[fixed]` (session 2) **[A1002-UP-11] (medium)** — the MCP host's serialized `enqueue` queue
  does not cover the chat executor, and each chat has only its own `isRunning`,
  so a chat batch and an MCP call (or two chats) can interleave on the same
  project at await points. No dangling pointers result, but dirty marks,
  snapshots and restore points reflect a state no single agent produced. Fix
  shape: one project-level mutation lock for chat + MCP.

- `[fixed]` (session 2) **[A1002-UP-12] (medium)** — the four `create_*` extension tools
  insert raw model-provided names without `getSafeName` or the lifecycle-name
  guard, while every editor path sanitizes (`create_extension "Platformer
  Helpers"` yields object types the editor can never produce;
  `create_custom_function "onCreated"` bypasses the lifecycle-reserved check).

- `[fixed]` (session 2) **[A1002-UP-13] (medium)** — `ApplyEventsChanges.js`
  `replace_all_actions` clears the target's actions before checking the
  replacement carries any; a replacement that is a comment/group event only
  wipes the target and still reports success.

- `[verified]` — `Utils/Serializer.js` (all six wrappers freed in `finally`),
  the instance-id resolver (**all five** call sites use it; no raw `startsWith`
  site remains), `LocalPreviewLauncher` exporter cleanup, the `didModifyProject
  === false` contract, `ByokSpriteTools` wrapper lifecycles (collision-mask
  polygons correctly NOT deleted), every `new gd.EventsList()` freed in
  `finally`, B-TOOL-11's debugger-bind gate, and strict sequential tool
  execution inside one loop (no intra-loop parallelism exists).

### 1.6 Persistence / UI / Electron

- `[fixed]` **[A1002-ELEC-15] (high, data integrity)** — `downloadFile` is typed
  `Promise<void>` whose only failure channel is a rejection, but the wired
  implementation resolved the main-side `{ok:false}` and the main handler never
  rejects. **Every** download failure (HTTP 404, byte cap, timeout, refused
  containment) was therefore treated as success: the resource was registered
  pointing at a file that was never written — or an existing resource was
  retargeted at a nonexistent one with `replace_existing`. The renderer wrapper
  now throws on `!result.ok`; two tests pin the failure and success paths.

- `[fixed]` **[A1002-UI-1] (high)** — picking a reasoning effort on a chat with
  **no** model selection created a `byokModelSelection` pinning `providerId: ''`
  (the global endpoint) instead of the resolved target's provider
  (`useByokChatSeam.js:605`). In a providers-only setup — the layout Phase 13.4
  itself ships — clicking the effort pill silently re-routed every later call of
  that chat to the global endpoint with the provider's model (auth failure /
  404), and blanked the model dropdown.

- `[fixed]` (session 2) **[A1002-UI-2] (medium)** — an in-flight immediate save captured the
  chat before `deleteChat` removed it, so the save can re-create the file and
  re-add the index entry after the delete: the deleted chat **resurrects** in
  the Recents rail with its full transcript (`ByokChatStore.js:52-63` vs
  `:241-252`).

- `[fixed]` (session 2) **[A1002-UI-3] (medium)** — `enforceQuota`'s orphan-sidecar sweep
  deletes EVERY `.images.json` when one `byok-chats-list` call returns
  `ok:false` (the IPC backend maps failure to `[]`, so everything looks
  orphaned): a transient userData-folder enumeration failure during any save
  permanently loses all chats' image payloads while the index self-heals.

- `[fixed]` (session 2) **[A1002-UI-4] (medium)** — a durable per-chat model selection
  referencing a since-removed provider silently resolves to the **global**
  endpoint with the dead model name and the legacy key slot — the same failure
  shape B-UI-9 fixed for routing profiles, which chat selections were not
  covered for (and which outlive providers inside saved chat files).

- `[fixed]` (session 2) **[A1002-UI-5] (medium)** — removing a provider unconditionally calls
  `clearByokKey(provider.keyRef)`; for the migrated provider #1 (`keyRef: ''`)
  this deletes the **legacy slot** the still-present "Single-endpoint fallback"
  section, the Test button and every `''`-routed call read.

- `[fixed]` (session 2, all five) **[A1002-ELEC-16…20] (low)** — five Electron-main items: `ensureStarted`
  has no in-flight mutex (double-toggle leaks a listening server);
  the snapshot-restore URL is unvalidated and the collection is dropped before
  the upload; ADS colons / reserved device names still accepted on the
  model-controlled resource path (B-ELEC-12 did not reach this path); the
  atomic-write temp name is fixed per pid+file (concurrent writers publish each
  other's buffer); `readySenders` survives a renderer reload so forwards can
  hang for the full 150 s.

### 1.7 MCP

- `[fixed]` (session 2) **[A1002-MCP-1] (medium)** — the queue slot-release timer is armed at
  **enqueue** time, so every call queued behind a hung head releases at ~the
  same instant and a burst starts near-simultaneously: concurrent mutating tools
  on the shared project. Arm the timer at task start instead.

- `[fixed]` (session 2) **[A1002-MCP-2] (low)** — a call the client was already told "timed
  out" still executes to completion when its slot arrives (no cancellation mark
  is planted on timeout), so a retried mutating tool runs twice.

- `[fixed]` (session 2) **[A1002-MCP-7] (low, security-ish)** — `update_project_notes` is
  `modifiesProject: false` and therefore reachable in MCP **read-only** mode: an
  external read-only agent can persistently rewrite the notes every future chat
  injects into its system prompt, while the card promises "Only read the
  project (no changes)".

- `[verified]` — the read-only gate is otherwise airtight (every mutating extra
  tool declares `modifiesProject: true` and every mutating registry tool is
  covered), `gdevelop://` resolution is exact-match with forced offline and no
  traversal, notification forwarding, correlation bookkeeping, timeout layering
  (120 s < 150 s < 180 s), auth on every route, 0600 discovery file, and the
  B-MCP-13 mirror mechanics.

### 1.8 Prompt and scripts

- `[fixed]` (session 2) **[A1002-PROMPT-1] (medium)** — the project-context section still
  teaches "EventScript cannot express an include, and no tool creates one yet"
  and asks the user to hand-add Include-external-events, which is **false** in
  the current tree (the parser builds link events, the writer round-trips them,
  and the pack and skill both teach `link "<sheet>"`). The B-PROMPT-5 reword
  fixed the section against capability the parser actually has.

- `[open]` **[A1002-PROMPT-3/4] (medium)** — the prompt→registry guard only
  extracts call-shaped tokens (`Name(`), so every **bare** tool mention escapes
  the check — the guard misses most of the prompt's actual tool teaching; and it
  scans only the *composed* text, which degrades 3 of 6 degradable sections, so
  the historically most defect-dense text (the EventScript pack) is never
  scanned.

- `[fixed]` (session 2) **[A1002-SCRIPT-1] (high)** — the 10 event-logic eval scorers reward
  the hosted backend's serialized **French** instruction vocabulary
  (`CreerObjet`, `DepartDeLaScene`, `ChangeScene`), which BYOK's local event
  writer **refuses**: the eval fails answers in the only format the real tool
  accepts and passes answers the real tool would reject.

- `[open]` **[A1002-SCRIPT-2] (medium)** — the eval harness sends a generic
  2-message chat with neither the BYOK system prompt nor any tool schemas while
  claiming to measure whether a prompt/skill/tool change helped; its scorers
  require argument names (`create_if_missing`, `brush_position`,
  `children_to_add`) the model was never shown — systematic false fails.

## Part 2 — Verification method notes

- Every `[fixed]` item above was regression-guarded: the new test was run
  against the code **with the fix reverted** and had to go red (CACHE-1, CACHE-2,
  LOOP-1, TOOL-1). Where a first attempt turned out to be vacuous — the reload
  test could not reach its scenario with the available fixture, and the original
  CACHE-2 spec never invoked the code at all — the test was rewritten to reach
  the real path and assert non-vacuity explicitly, rather than left as false
  confidence.
- Baseline before this session's changes: 235 suites / 2628 tests, lint 0/0, Flow
  0, prettier clean, with `useByokChatSeam.spec.js` failing on the documented O4
  mock-bleed flake (passes standalone).

## Part 6 — Disposition (second session, owner-ordered "implement all fixes")

The owner ordered every remaining finding implemented, plus improvements found
along the way. **49 of the ~50 findings in this audit are now fixed and tested**;
the ones still open are listed in `outofscoped.md`.

### Fixed in the second session

**RAG.** `[fixed]` **A1002-RAG-1** — the Qdrant backend was upload-only. The
store gained a real `search` (Qdrant `points/search`, payloads rebuilt into
hits) and `inspect` (status + point count); `searchByokRagKnowledge` now takes
the semantic path when a `qdrantSearch` dep exists even with a null local
index; `loadPersistedByokRagIndex` gained a Qdrant branch that verifies the
collection holds points and installs the search closure; the rebuild and the
status card follow the server, so the card can no longer claim healthy while
search is lexical. **The previously untested remote branch now has 5 tests.**
`[fixed]` **A1002-RAG-2** — `saveIndex` deletes the points beyond the new count.
`[fixed]` **A1002-RAG-3** — the snapshot upload gets its own 5-minute timeout
(the `?wait=true` call blocks on a multi-tens-of-MB asset), the timeout is
tagged `clientTimedOut` end-to-end, and that path no longer drops the
collection — dropping while the server may still be importing deletes data in
progress. `server-side URL validation` too (see ELEC-17). `[fixed]`
**A1002-RAG-5** — the lexical half is no longer AND-only: partial matches are
ranked below every full match, and a prefix match rescues inflections
("animations" vs "animation"). RAG is off by default, so this is the mode most
users are in. `[fixed]` the persisted-load latch now only latches after an
*actual* attempt (RAG-9), so enabling RAG mid-session loads the on-disk index
instead of staying lexical until a restart. Improvements: the minified-docs
accessor memoizes its 2.3 MB validated page list (CACHE-5) and the lexical
pass uses a per-corpus lowercase view instead of rebuilding it per query
(CACHE-6).

**Loop.** `[fixed]` **A1002-LOOP-4** — response validation now rejects a
non-text `content` (which made every turn look like an empty answer) and a
non-string `function.arguments`, normalizing an absent one to `{}` instead of
replaying a `tool_calls` message strict endpoints 400 on. `[fixed]`
**A1002-LOOP-5** — the compaction summarizer carries the loop's cancellation
handle, so Stop really stops it. `[fixed]` **A1002-LOOP-6** — a turn-budget
error is non-retryable (Retry was a dead button that re-marked the identical
error). `[fixed]` **A1002-TOOL-7/8** — the loop guard snapshots its history per
batch and rolls it back when the user refused or a suspension interrupted the
batch, so a tool that never ran cannot kill the chat; and it now detects an
ALTERNATING cycle (A,B,A,B…), which its trailing-streak rule never saw.

**Tools.** `[fixed]` **A1002-TOOL-3/9** — `inspect_runtime_state` and
`read_runtime_details` now honor `scene_name` / `variable_paths` (both were
advertised and ignored, so a narrow query got the full dump), and the dump caps
instances per object at 50, reporting each cut group in
`truncatedInstanceGroups` instead of a silent mid-JSON cut by the generic cap.
`read_runtime_details` gained the two schema fields it now honors. `[fixed]`
**A1002-TOOL-4** — `list_effects` is capped with a `truncated` flag and the real
total, so the usage note survives. `[fixed]` **A1002-TOOL-5** — the preserved
block reads `args.name` (`load_skill`'s real argument), so "Loaded skills" is
no longer permanently empty after a compaction. `[fixed]` **A1002-TOOL-6** —
`read_events_source`'s `max_chars` description matched the implementation
(default 12000, clamped 2000–30000). `[fixed]` **A1002-TOOL-11** —
`read_doc_page` moved into the core advertised set (three prompt surfaces and
every docs-min chunk teach it, so the common case must offer it), and the
advertisement is now DEDUPED so a tool in both sets cannot produce a duplicate
`tools` entry, which strict endpoints reject.

**Persistence / UI.** `[fixed]` **A1002-UI-2** — a save re-checks the chat still
exists immediately before writing, so a chat deleted mid-save can no longer be
resurrected with its transcript. `[fixed]` **A1002-UI-3** — the storage backend
now REJECTS a failed listing instead of resolving `[]` (an empty listing made
every sidecar look orphaned, and the quota sweep deleted all of them), and the
sweep additionally skips when a non-empty index met an empty listing.
`[fixed]` **A1002-UI-4** — a chat selection naming a since-deleted provider now
falls through to normal profile/global resolution instead of sending that
provider's dead model to the global endpoint. `[fixed]` **A1002-UI-5** —
removing a provider no longer clears the shared legacy key slot
(`keyRef === ''`), which the "Single-endpoint fallback" section still reads.
`[fixed]` **A1002-CACHE-4** — the models cache is keyed by (URL, provider id), so
two providers on one aggregator URL no longer overwrite each other's model list.

**MCP.** `[fixed]` **A1002-UP-11** — a new project mutation lock
(`ByokMutationLock.js`, FIFO, exception-safe) is taken at three doors: the chat
orchestrator's per-batch execution section, the MCP registry executor and the
MCP intercepted-tool executor. The chat never holds it across a model request
or an approval prompt. `[fixed]` **A1002-MCP-1** — the queue slot-release timer
is armed when a task STARTS, not when it is enqueued, and the chain extends
synchronously: a burst queued behind a hung head no longer releases together
and runs concurrent mutating tools. `[fixed]` **A1002-MCP-2** — a call the client
was already told "timed out" is marked cancelled, so a still-queued mutating
tool is skipped instead of running twice on a retry. `[fixed]`
**A1002-MCP-5** — the main-process activity validator bounds every string
field, requires a finite non-negative duration, and stores a whitelisted copy.
`[fixed]` **A1002-MCP-7** — `update_project_notes` is refused in MCP read-only
mode by name: it is `modifiesProject:false` (no gd object changes, so the chat's
approval row rightly ignores it) yet it rewrites the text every future chat
injects into its system prompt.

**Electron.** `[fixed]` **A1002-ELEC-16** — `ensureStarted` has an in-flight
mutex (mirroring `ByokQdrant`'s `setupInFlight`); the double-toggle that leaked
a listening server is gone. `[fixed]` **A1002-ELEC-17** — the snapshot URL is
validated (https + `github.com` + the GDevelop release path prefix) in BOTH
the pure core and the main handler, BEFORE any download, drop or fetch; a
